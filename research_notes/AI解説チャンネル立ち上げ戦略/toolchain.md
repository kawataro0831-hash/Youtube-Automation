## Key Question 1 — Remotion: version, cadence, license, relevant packages, cloud rendering, AI/agent features

### Takeaway
Remotion is still on the 4.0.x line (v4.0.537 as of 19 Oct 2026, releasing roughly every 2–4 days); Remotion 5.0 is announced but "not yet released". A solo individual or a company with ≤3 people uses Remotion free, including commercially and for automated renders; the paid Company License ($25/seat/mo "Creators" or $0.01/render with $100/mo minimum "Automators") only applies at 4+ headcount. The official AI route is now "Remotion Agent Skills" (`npx skills add remotion-dev/skills`), and the Remotion MCP is deprecated.

### Cited Findings

### Inferences
- For this creator (solo individual / one-person company), Remotion is $0 in licensing regardless of how many renders they automate; the only paid item would be AWS cost if they use Lambda. Under the planned 5.0 rules they will simply pass `"free-license"` as the license key.
- The "10 minute Remote HD video ≈ $0.10" figure is for a composition that embeds a remote video; a 10–15 min 1080p explainer with heavy React animation but no embedded video should land in the same $0.05–$0.30 range on Lambda. 4K cost scales roughly with pixel count: extrapolating the 10 s 4K example ($0.013–0.014) linearly gives roughly $0.8–1.0 for a 10-minute 4K render — treat as an order-of-magnitude estimate, not a measurement.
- Because the creator already has local rendering, Lambda is optional; the main reasons to add it would be 4K renders or parallelising multi-episode batches.
- The 5.0 changes (WebGL on by default, Mediabunny replacing `getVideoMetadata`, `layout="none"` removal in `TransitionSeries`) are the ones most likely to touch an existing 2D-compositing pipeline; `@remotion/three` scenes will benefit from the default `angle` renderer.

## Key Question 2 — Blender for explainer animation (features, CPU render realism, creators, AI agents)

### Takeaway
Blender's current stable line is 5.2 LTS (5.2.3 on the release branch; 5.3 is in beta and `main` is already 5.4 alpha), supported until July 2028 per third-party coverage. Official docs were unreachable, so feature claims about Grease Pencil 3 / EEVEE / Geometry Nodes in 5.x rest on third-party release coverage. For CPU-only rendering at 15–45 s/frame, every 30 s of 1080p 3D footage costs 4–11 hours, so 3D should be reserved for short inserts, stills, or EEVEE. Blender MCP ("MCP for Blender") is a mature third-party bridge that lets Claude Code/Desktop write bpy directly.

### Cited Findings
- Blender source mirror: `blender-v5.2-release` branch header defines `BLENDER_VERSION 502`, `BLENDER_VERSION_PATCH 3`, cycle `release`, suffix `LTS` (i.e., 5.2.3 LTS). — [BKE_blender_version.h (5.2 branch)](https://raw.githubusercontent.com/blender/blender/blender-v5.2-release/source/blender/blenkernel/BKE_blender_version.h)

- Third-party coverage (snippets only): Blender 5.2 LTS released July 14, 2026; supported until July 2028; experimental node-based physics in Geometry Nodes (XPBD hair/cloth); LoopTools-derived Circle/Space/Flatten tools; "Grease Pencil: A completely redesigned Fill tool algorithm"; Cycles texture cache and Principled BSDF "Thin Wall" mode; "EEVEE gained instancing optimizations, so CPU-bottlenecked, instancing-heavy scenes being up to twice as fast"; online asset libraries; official notes at blender.org/download/releases/5-2-lts/. — [GameFromScratch](https://gamefromscratch.com/blender-5-2-lts-released/); [Phoronix](https://phoronix.com/news/Blender-5.2-Released); [OSArch](https://osarch.org/2026/07/15/blender-5-2-lts-released/); [UbuntuHandbook](https://ubuntuhandbook.org/index.php/2026/07/blender-5-2-released-with-new-lts-with-2-years-of-support/)
- Blender MCP (third-party, MIT): "Connect Blender to any LLM"; PyPI package renamed `blender-mcp` → `mcp-for-blender`; one-command setup detects "Claude Desktop, Claude Code, Codex, Cursor, VS Code, Devin Desktop/Windsurf, OpenCode, Antigravity"; Claude Code install is `claude mcp add blender uvx mcp-for-blender`. Features: two-way socket communication; object/material manipulation; "Visual verification: Multi-angle, camera, wireframe, X-ray and animation-strip views, plus renders, so the AI checks its own work"; "Code execution: The AI writes Blender Python directly"; asset import from Poly Haven, Sketchfab, Poly Pizza, and AI model generators (Meshy, Tripo, Hyper3D Rodin, Hunyuan3D; a paid "Premium" tier removes the need for own API keys). "Disclaimer: This is a third-party integration and not made by Blender." — [ahujasid/blender-mcp README](https://raw.githubusercontent.com/ahujasid/blender-mcp/main/README.md)
- Blender's own license is GPL (not re-verified this session; see Gaps).

### Inferences
- Render-time arithmetic from the creator's own numbers (15–45 s per 1080p frame, CPU only): 30 fps × 30 s = 900 frames → 3.75–11.25 h; 60 s → 7.5–22.5 h; 3 min of 3D per episode → 22–67 h. 4K has 4× the pixels, so expect ~60–180 s/frame and 4× the wall-clock (unless rendering 1080p and upscaling 2D-composited output). This means 3D must be budgeted in seconds per episode, rendered overnight, or switched to EEVEE (rasteriser; far faster than Cycles on CPU) / Workbench-style flat shading, which also suits the Kurzgesagt/Branch-style flat look better than path-traced Cycles.
- A pragmatic split: Remotion for 95% of screen time (text, diagrams, 2D motion, captions) and Blender only for hero 3D shots (chip die, GPU, data-centre fly-through), rendered as short PNG/ProRes sequences with alpha and composited in Remotion via `@remotion/media` `<Video>` or `<Img>` sequences.
- For Branch-Education-style cutaway hardware, Grease Pencil line art + flat materials in EEVEE is the common approach; this is inference from the feature set, not from a creator's published workflow (see Gaps).
- With the creator already scripting bpy, Blender MCP adds little beyond visual self-verification by the agent; its main value is letting Claude Code iterate on scene setup while checking renders, which fits a CPU-only box if render previews are kept small.

### Gaps
- `docs.blender.org`, `developer.blender.org`, and `blender.org` were all blocked; no official release notes for 5.0/5.1/5.2 or Grease Pencil 3 / EEVEE Next / Freestyle docs could be read. Feature statements are from third-party coverage only.
- No usable sources were found on Branch Education, Animagraffs, or Posy workflows (the search returned unrelated courses); their behind-the-scenes posts could not be located within the search budget.
- No benchmark source for EEVEE vs Cycles CPU frame times in 5.x was found; the EEVEE "up to 2x" claim is about instancing-heavy scenes only.
- Blender Studio and official "Blender for motion graphics/explainer" material not consulted.

## Key Question 3 — Gemini TTS: current models, pricing, languages, voices, controls, output, terms, watermark; comparison with Cloud TTS, ElevenLabs, OpenAI, VOICEVOX; Japanese quality reviews

### Takeaway
As of October 2026 the current Gemini TTS models are `gemini-3.8-flash-tts` and `gemini-3.8-flash-lite-tts` (GA in the Gemini API per the Sept 22, 2026 changelog; "Preview" on Vertex/Cloud TTS pricing), with 30 prebuilt voices, a Voices API for voice design/replication, `speech_metadata` style control, inline vocal tags, multi-speaker, and 24 kHz 16-bit mono WAV/PCM output. Google Cloud's official pricing lists 3.8 Flash TTS at $0.50/M text tokens in + $9.00/M audio tokens out through Dec 31, 2026 (rising to $1.00/$18.00 from Jan 1, 2027), at 25 audio tokens per second — i.e., about $0.14–$0.27 for a 10-minute narration. Gemini 2.5 TTS previews and 3.1 Flash TTS preview are being retired. Japanese-language reviews of 3.1/2.5 Gemini TTS rate the Japanese as near-human for narration but note it is use-case dependent.

## Key Question 4 — English audio track generation (dub of the same script)

### Takeaway
Three routes: (a) generate the English narration with the same Gemini 3.8 TTS pipeline (same ~$0.15–0.30 per 10-minute take, one English voice/style prompt; multi-language support claimed at 70+ languages), (b) ElevenLabs Dubbing (pricing not verifiable this session), or (c) YouTube's free auto-dubbing, which is now available to all creators with Japanese as a supported source language into English, though its more natural "expressive speech" mode does not yet cover Japanese per secondary sources.

### Cited Findings
- YouTube auto-dubbing: a Feb 2026 report says auto-dubbing became available to all users (after a Dec 2024 start for Partner Program "knowledge and information" channels); Japanese is listed among source languages that can be dubbed into English; counts of 27 vs. 29 source languages conflict across sources; "expressive speech" covers 8 languages and Japanese is not among them; YouTube warns that accents, proper nouns, idioms and jargon cause errors (all snippets only). — [outlierkit](https://outlierkit.com/resources/youtube-auto-dubbing-all-creators-global-growth-2026/); [sync.so](https://sync.so/blog/youtube-auto-dubbing); [tbsnews](https://www.tbsnews.net/node/1353236); [YouTube Help: Automatic dubbing](https://support.google.com/youtube/answer/15569972) (not opened)
- Gemini 3.8 TTS supports voice style prompts with explicit accent instructions (e.g., "British English accent as heard in Brixton, London") and Voice Design from a text description ("A warm, expressive British documentary narrator..."). — [Get_started_TTS.ipynb](https://raw.githubusercontent.com/google-gemini/cookbook/main/quickstarts/Get_started_TTS.ipynb)
- Gemini 3.1 Flash TTS marketed as 70+ languages; ElevenLabs v3 "70+ languages supported". — [DataNorth](https://datanorth.ai/news/google-gemini-3-1-flash-tts-release) (snippet); [elevenlabs-python README](https://raw.githubusercontent.com/elevenlabs/elevenlabs-python/main/README.md)
- YouTube multi-language audio tracks are the delivery mechanism for a creator-supplied English dub (same video, additional audio track) — mechanism not re-verified this session (see Gaps).

### Inferences
- Cheapest high-control option: translate the Japanese script with an LLM, keep timing by section, generate English with Gemini 3.8 TTS (≈$0.15–0.30 per 10 min), and upload as a second audio track; the English SRT already produced for subtitles doubles as the dub script. Total incremental cost per episode: well under $1 plus the creator's QA time (~30–60 min to check pronunciation of technical terms).
- YouTube auto-dub is $0 and zero effort but offers no control over voice or terminology; because Japanese is excluded from "expressive speech", the English dub from Japanese will sound flatter. A reasonable plan: enable auto-dub at launch, replace with a Gemini-generated track for episodes that gain traction.
- Because Gemini TTS output lengths must be timed to the Japanese visuals, English (typically longer when spoken) may need a "slightly faster pace" style instruction or per-segment generation aligned to Remotion `Sequence` boundaries.

### Gaps
- YouTube Help page for auto-dubbing and for multi-language audio tracks could not be opened; language lists and eligibility details are from secondary sources.
- ElevenLabs Dubbing pricing/minute allowances not retrievable.

## Key Question 6 — Realistic per-episode budget and time for a solo creator with this stack (TTS, cloud render, music/stock licensing)

### Takeaway
With Remotion free, Blender free, and Gemini TTS at roughly $0.15–0.30 per 10-minute take, the hard cash cost of a 10–15 min episode is on the order of $1–3 unless the creator adds Lambda 4K renders (~$1), AI B-roll (~$10+), or a music subscription (Epidemic Sound commercial tier reported at $29–49/mo; Artlist ~$199–299/yr). Time, not money, is the constraint: CPU-only Blender at 15–45 s/frame makes each 30 s of 3D cost 4–11 hours of render time, so the realistic schedule is dominated by scripting, Remotion scene-building, and Blender render queues rather than any API bill.

### Cited Findings
- Remotion: free for individuals and ≤3-person companies, including automation and commercial use. — [License FAQ](https://raw.githubusercontent.com/remotion-dev/remotion/main/packages/docs/docs/license/faq.mdx)
- Remotion Lambda measured costs: 10-min remote HD video ≈ $0.10–0.11; 10 s 4K ≈ $0.013–0.014; plus S3/CloudWatch extras. — [Lambda cost example](https://raw.githubusercontent.com/remotion-dev/remotion/main/packages/docs/docs/lambda/cost-example.mdx)
- Gemini 3.8 Flash TTS: $0.50/M text tokens in, $9.00/M audio tokens out through 2026-12-31 ($1.00/$18.00 from 2027-01-01); Flash-Lite $0.50/$6.00 ($1.00/$12.00); 25 audio tokens per second. — [Cloud Text-to-Speech pricing](https://cloud.google.com/text-to-speech/pricing)
- Chirp 3: HD: 1M characters/month free, then $30/M. — [Cloud Text-to-Speech pricing](https://cloud.google.com/text-to-speech/pricing)
- Veo 3.1 Fast ≈ $0.10–0.30/s by resolution (aggregator, snippet). — [benchlm.ai](https://benchlm.ai/media-pricing/veo)
- Music licensing (snippets only; figures conflict): Epidemic Sound requires its Commercial plan for monetized YouTube channels; official page says the commercial plan covers "monetizing up to three channels per platform and client work"; third-party prices range from ~$29/mo to $49/mo (or $228/yr ≈ $19/mo). Artlist is annual-only: ~$199/yr music, $299/yr music+SFX, or $249/yr "all-in-one" per 2026 comparison. — [Epidemic Sound commercial subscription](https://www.epidemicsound.com/commercial-subscription/); [earnifyhub comparison](https://earnifyhub.com/blog/epidemic-sound-vs-artlist); [wyzowl review](https://www.wyzowl.com/epidemic-sound-review/); [videoblocksreview comparison](https://www.sites.google.com/site/videoblocksreview/royalty-free-music/epidemic-sound-vs-artlist)
- Google's cookbook points to Lyria 3 / Lyria RealTime for generating "custom instrumental tracks or full songs" to pair with Gemini TTS voiceovers (commercial terms not stated there). — [Get_started_TTS.ipynb](https://raw.githubusercontent.com/google-gemini/cookbook/main/quickstarts/Get_started_TTS.ipynb)
- VOICEVOX (if used for a second character voice) is free with mandatory credit. — [VOICEVOX 利用規約](https://raw.githubusercontent.com/VOICEVOX/voicevox_resource/main/editor/README.md)

### Inferences (per 12-minute episode, 1080p, Japanese + English subtitles)
- Narration (Gemini 3.8 Flash TTS): 720 s × 25 = 18,000 audio tokens → $0.16 (2026 promo) / $0.32 (2027) per take; budget 3 takes → $0.5–1.0. Optional English dub track: same again. Script-writing/translation LLM calls: typically cents, not estimated here.
- Rendering: local = $0 (electricity only). Lambda 1080p ≈ $0.10–0.30; Lambda 4K ≈ $1 (extrapolated). Blender CPU: 30–60 s of 3D inserts = 4–22 h unattended render; 4K roughly ×4.
- Music/SFX: $0 with YouTube Audio Library (terms not re-verified), ~$19–49/mo Epidemic Sound commercial, or ~$17–25/mo amortised Artlist; per episode at 4 episodes/month ≈ $5–12. Suno/Flow/Lyria commercial terms were not verifiable this session and should be checked before relying on AI music for monetized videos.
- AI B-roll (optional): $0 if omitted; ~$10–30/episode if 10–20 Veo Fast clips are used.
- Cash total: ~$1–3/episode without AI B-roll or paid music; ~$15–45/episode with a music subscription and moderate Veo B-roll.
- Time (solo, assuming the pipeline is already scripted and agent-assisted): research + script 4–8 h; storyboard + Remotion scene code 8–16 h (the 2D "分かりやすいアニメーション" work is the long pole); Blender insert modelling 2–6 h plus unattended render 4–22 h; TTS + caption timing + QA 1–2 h; final render/upload/metadata 1 h. Roughly 20–35 working hours per episode plus overnight renders, which supports a 1 episode/week cadence at most for one person. These time figures are the researcher's estimates, not sourced.

- No source for electricity/hardware cost of local CPU rendering; omitted.
